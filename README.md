# AI Logo Decision Funnel

[English](README_EN.md) | 中文

AI Logo Decision Funnel 是一个开源的 AI Logo 设计漏斗工具。它不是直接把一句模糊需求丢给生图模型，而是把用户需求拆成一层层可比较、可选择、可回退的决策流程：先理解需求，再生成方向，再筛选细节，最后产出可执行的 Logo 方案、正向 Prompt、负向 Prompt，并可继续对接图片生成接口。

这个项目当前用于 Logo 设计场景，但我更希望它被看作一套可复用的 AI 落地方法：把“用户不知道怎么表达的模糊目标”变成“模型可以稳定执行的结构化任务”。欢迎其他开发者沿用这套漏斗筛选逻辑，把它迁移到更多 AI 应用场景，比如广告素材生成、商品图生成、短视频脚本、品牌定位、装修方案、营销文案、教育辅导、企业知识库问答等。

## Core Idea

很多 AI 产品失败不是因为模型不会回答，而是因为用户一开始给出的需求太模糊，系统又过早进入最终生成。这个项目的核心逻辑是：不要一步到位生成结果，而是用漏斗逐步收敛。

1. **需求理解层**
   用户输入自然语言需求，系统先解析品牌类型、目标用户、气质、偏好元素、颜色、使用场景、限制条件和不确定点。

2. **方向发散层**
   系统基于需求生成 5 个彼此区分的设计方向，让用户先选择“大方向”，避免直接陷入细枝末节。

3. **细节筛选层**
   用户选定方向后，系统再生成图形主体、结构、复杂度、线条、字体、层级、色彩、应用优先级和规避规则等模块化选项。

4. **方案确认层**
   系统把用户选择重新组装成 Logo 方案说明，并生成正向 Prompt 与负向 Prompt，确保最终输出与用户选择一致。

5. **生成交付层**
   最终 Prompt 可以继续传给图片生成接口，完成从需求到结果的闭环。

这套逻辑的关键不是 Logo，而是“先发散，再筛选，再结构化生成”。任何需要把用户意图转换成 AI 可执行任务的产品，都可以参考这个模式。

## What It Does

- 将模糊 Logo 需求解析为结构化品牌理解
- 生成 5 个可比较的设计方向
- 通过模块化选项逐步筛选 Logo 细节
- 自动生成 Logo 方案卡片、正向 Prompt 和负向 Prompt
- 支持 Responses-compatible 文本模型接口
- 支持图片生成接口对接
- 使用 Zustand 在本地保存流程状态，方便跨页面继续

## Installation

Clone the repository:

```bash
git clone https://github.com/CraLy1245/ai-logo-decision-funnel.git
cd ai-logo-decision-funnel
```

Install dependencies:

```bash
npm install
```

Create a local environment file:

```bash
cp .env.local.example .env.local
```

On Windows PowerShell, you can use:

```powershell
Copy-Item .env.local.example .env.local
```

Fill in your own API settings in `.env.local`:

```bash
RIGHT_CODES_API_KEY=your_api_key_here
RIGHT_CODES_BASE_URL=https://www.right.codes/codex/v1/responses
RIGHT_CODES_MODEL=gpt-5.5
RIGHT_CODES_IMAGE_API_KEY=your_image_api_key_here
RIGHT_CODES_IMAGE_BASE_URL=https://www.right.codes/draw/v1/images/generations
RIGHT_CODES_IMAGE_MODEL=gpt-image-2-vip
```

Run the development server:

```bash
npm run dev
```

Open `http://localhost:3000` in your browser.

## How To Use

1. Open the home page and enter a rough Logo requirement, for example brand type, target users, tone, visual preference, use case, and constraints.
2. Review the structured requirement analysis generated by the model.
3. Compare the generated design directions and select the one that best matches the product or brand.
4. Continue into the detail step and adjust the module options.
5. Generate the final plan and Prompt.
6. Copy the Prompt into your own image model, or configure the image API variables and generate directly from the result page.

## Environment Variables

This project does not include any real API keys. Keep your real key only in `.env.local`, which is ignored by Git.

| Variable | Description |
| --- | --- |
| `RIGHT_CODES_API_KEY` | API key for the text/model provider |
| `RIGHT_CODES_BASE_URL` | Responses-compatible text/model endpoint |
| `RIGHT_CODES_MODEL` | Model name used for requirement analysis, direction generation, detail generation, and prompt generation |
| `RIGHT_CODES_IMAGE_API_KEY` | Optional image API key when the image endpoint uses a separate key |
| `RIGHT_CODES_IMAGE_BASE_URL` | Image-generation API endpoint |
| `RIGHT_CODES_IMAGE_MODEL` | Image model used by the result page |

## Adapting The Funnel To Other AI Products

To reuse this project outside Logo design, keep the funnel shape and replace the domain schema:

- Replace the requirement analysis fields with the core variables of your domain.
- Replace the 5 design directions with 5 strategic solution directions.
- Replace detail modules with the decisions users must make before generation.
- Keep strict JSON contracts between model calls and UI state.
- Generate final prompts only after the user has selected enough structured constraints.

For example, an ecommerce image workflow could use:

- product analysis
- 5 image strategy directions
- scene, angle, lighting, props, selling point, objection-handling modules
- final image prompt and negative prompt

The important principle is to let users make high-leverage choices before the model generates the final artifact.
